# P05-R1.7 — Privacy export/delete & account lifecycle

> **Phạm vi:** remediation slice **P05-R1.7** (giai đoạn ủy quyền liên tục của
> PO ngày 24/10/2026 — xem
> [PO-CONTINUOUS-DELEGATION-2026-10-24](../00-process/PO-CONTINUOUS-DELEGATION-2026-10-24.md)).
> Bằng chứng **local/hermetic** (memory + PGlite). **Không** phải proof trên
> managed staging/production. Gói export được lưu private trong object storage
> nội bộ; link tải ngắn hạn và queued-job wrapper là mục mở (§5).

## 1. Yêu cầu (P03 `IDENTITY-AUTHORIZATION-PRIVACY-AND-RETENTION.md` §7)

- **Export:** gói tối thiểu gồm profile/consent, projects/artifacts metadata +
  text nguồn, journeys/attempts/proofs, XP ledger, footprint categories/
  preferences; tạo async, owner-only, có audit.
- **Delete footprint:** dừng dùng cho ranking mới ngay, xóa FootprintEvent chi
  tiết và derived personalization, **không** xóa project/journey/proof/XP,
  trả receipt.
- **Delete account:** thu hồi sessions + chặn truy cập ngay; tombstone
  projects/artifacts/journeys/proofs/footprint; module đã review ẩn/attribution
  dạng đã xóa; audit/XP giữ dạng pseudonymous theo retention; receipt nói rõ
  phạm vi giữ lại.
- Contract API đã khóa ở P03: `POST/GET /me/data-requests`, `GET/PATCH
  /me/personalization`, `DELETE /me/personalization/footprint`; events
  `identity.data_request.created`/`.completed`; schema `DataRequest`
  (status `received|processing|completed|partially_completed|rejected|failed`).

## 2. Đã triển khai

### 2.1 Domain + persistence

- `DataRequestRecord` + collection `dataRequests` (bảng `data_requests` 0002
  sẵn có) — lifecycle `requested → processing → completed|failed`; DTO map
  `requested→received`, `cancelled→rejected` đúng contract.
- `FootprintEventRecord` + collection `footprintEvents` (bảng `footprint_events`
  0005): append-only nhưng **cho phép hard-delete khi privacy erasure** (flush
  xóa theo `id` bigint; bản ghi tạo-then-delete trong cùng transaction không
  chạm DB).
- `PersonalizationRecord` + bảng mới **`user_personalization` (migration 0009)**
  cho preferences/version; RLS deny-by-default như mô hình 0008.
- `footprintEnabled` lấy **consent `personalization_footprint` làm nguồn sự
  thật** (PATCH ghi consent + emit `identity.consent.changed`); signal groups
  (`search_history`, `learning_activity`, `candidate_votes`,
  `artifact_topics`) tường minh trong code.

### 2.2 Service core (`service.ts`) + routes

- `createDataRequest` (202, idempotent replay 200), `getDataRequest`
  (owner-only), `deleteFootprint` (shortcut đúng contract DELETE),
  `getPersonalization`/`patchPersonalization`.
- `processDataRequest(requestId)` — processor entry chạy trong Unit of Work
  (cùng hình mẫu worker entries của R1.5; queued-job wrapper là mục mở):
  - **export:** build bundle `gon.privacy.export/1.0` (đủ 8 nhóm dữ liệu P03),
    lưu object `private/exports/{userId}/{requestId}.json` qua ObjectStorage
    port, receipt `{objectKey, sha256, expiresAt(+24h), contents}`.
  - **delete_footprint:** xóa FootprintEvent chi tiết của user, xóa
    personalization, tắt footprint consent; receipt
    `{deletedFootprintEvents, footprintDisabled, retained:[projects,journeys,
    proofs,xp_ledger]}`.
  - **delete_account:** thu hồi sessions, tombstone user (status `deleted`),
    tombstone projects/artifacts/chunks/journeys/proofs + xóa object storage,
    xóa footprint, ẩn module version đã `internal_reviewed` → `private` +
    anonymize attribution, anonymize profile/identity-link email; **giữ** XP
    ledger/audit/receipts dạng pseudonymous (ghi rõ trong receipt theo P03).
- Events `identity.data_request.created`/`.completed` qua transactional
  outbox + audit log cho mọi transition.

Điểm chứng minh chính:

1. **Export lifecycle:** create → `received` → process → `completed` với
   receipt hợp lệ; bundle object chứa đủ projects/artifacts/consents/
   footprint; owner-only (user khác bị `RESOURCE_NOT_FOUND`); idempotent
   replay trả cùng request; outbox có đủ `identity.data_request.created` +
   `.completed`.
2. **Delete footprint:** xóa đúng 2 event của user (giữ event user khác),
   xóa preferences, tắt footprint consent, receipt `retained` đúng 4 nhóm;
   project **không** bị xóa.
3. **Delete account:** user `deleted` + `deletedAt`, session bị thu hồi,
   project/artifact tombstoned, footprint trống, profile = "Người dùng đã xóa",
   receipt `retained` chứa `xp_ledger_entries`/`audit_logs`/
   `data_request_receipts`.
4. **PG round-trip:** mọi transition ghi qua UoW bền vững trong
   `data_requests`/`footprint_events`/`user_personalization`; hard-delete
   footprint events hoạt động transactional.
5. **RLS:** scoped role `gon_scoped_r17` không thấy gì khi thiếu GUC, chỉ thấy
   dòng của đúng user với `gon.user_id`; owner/service thấy tất cả.

## 4. Quyết định triển khai (trong phạm vi R1.7, không tạo `D-*` mới)

1. **`footprintEnabled` = consent** thay vì cột riêng — một nguồn sự thật,
   PATCH tự ghi consent + event (khớp machine `identity.consent.changed`).
2. **Hard-delete** footprint_events/user_personalization trong flush (ngoại lệ
   so với quy tắc "không xóa qua UoW" của các collection khác) vì P03 yêu cầu
   xóa chi tiết — chunks vẫn là tombstone riêng.
3. **Export bundle lưu ObjectStorage private** với receipt
   `objectKey/sha256/expiresAt` — đúng chuẩn key `private/` của R1.4; hợp
   đồng P03 **không có** endpoint tải file nên receipt giữ objectKey + hạn dùng;
   luồng tải là contract gap (§5).
4. **`processDataRequest` chạy đồng bộ trong UoW** (Alpha) — cùng hình mẫu
   `processQueuedBrewJob`; job type `data_request` cho hàng đợi bền vững là
   bước tiếp theo, không đổi domain logic.
5. **Module versions** chỉ ẩn `internal_reviewed → private` + anonymize
   attribution (đúng mức P03 yêu cầu); không xóa content đã public khác vì
   nhánh của user khác giữ snapshot học tập.
6. **XP ledger/audit/receipts giữ nguyên** theo lịch retention (24 tháng audit
   Alpha) — receipt ghi rõ `retained` + `retentionPolicy` thay vì hứa xóa
   tuyệt đối (P03 §6).

## 5. CÒN MỞ sau R1.7

1. **Link tải export ngắn hạn**: P03 chưa có endpoint download bundle — cần
   contract amendment (P03 process) hoặc luồng out-of-band; hiện receipt mang
   `objectKey` + `expiresAt` cho operator.
2. **Queued job `data_request`** trên durable job queue + worker loop (R1.5
   runtime) cho tải production; xử lý retry/dead-letter riêng cho privacy SLA
   (30 ngày theo P03).
3. **Sweeper xóa object/storage derived** (chunks/embeddings) cho account
   deletion quy mô lớn + đo thời gian hoàn tất 30 ngày trên staging thật.
4. **Auth.js session revocation** (hiện xóa dev sessions; với DB sessions của
   R1.4 cần nối `sessions`/`accounts` khi Auth thật bật).
5. **Personalization preferences schema** (hiện `object` tự do) — cần rule
   validation khi V2.1 footprint algorithm dùng thật.
