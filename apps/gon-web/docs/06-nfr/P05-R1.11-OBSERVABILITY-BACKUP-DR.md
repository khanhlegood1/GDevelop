# P05-R1.11 — Observability, backup/restore & DR

> **Nhóm:** P05 remediation — observability/logs có cấu trúc, readiness sâu,
> backup/restore scripts, DR runbook. **Ngày:** 24/10/2026. **Trạng thái bằng
> chứng:** **local/hermetic** (vitest + `bash -n`). Backup/restore/DR và mọi
> hạng mục cần hạ tầng thật nằm trong mục **NOT RUN** — không có kết quả
> production/DR drill nào được claim.

## 1. Phạm vi lát cắt

1. **Structured observability** (`src/server/observability.ts`): một dòng JSON
   cho mỗi sự kiện; `sanitizeLogFields` chặn mọi key mang secret/nội dung
   learner (body/prompt/content/token/cookie/email/invite/embedding…) trước
   khi serialize; access log `http_request` cho **mỗi** request `/v1`
   (requestId, method, route, status, durationMs, userId, outcome) — không
   bao giờ log query string/body.
2. **Readiness sâu** (`health.ts` + `db.ts`):
   - `migrations`: đối chiếu file `db/migrations` với bảng
     `gon_schema_migrations` — migration chưa apply → **`not_ready`
     (fail-closed)**, deploy phải chạy `migrate.mjs` trước khi nhận traffic.
   - `outbox`: đếm backlog `pending/failed` cũ hơn 15 phút — **report +
     alert, KHÔNG gate readiness** (xem quyết định D3).
   - Mở rộng `POSTGRES_REQUIRED_TABLES` thêm **14 bảng** còn thiếu
     (`quota_reservations`, `feature_flags`, `data_requests`,
     `user_personalization`, `footprint_events`, `ai_runs`, `abuse_*`,
     `budget_alert_claims`, …) — readiness fail-closed với schema R1.6–R1.10.
   - `readyz` log `readiness_not_ready` (mã lỗi check, không lộ topology).
3. **Backup/restore/DR** (`scripts/backup/`): `backup-postgres.sh`
   (pg_dump custom + sha256 + integrity list), `restore-postgres.sh`
   (checksum + restore vào **scratch DB**, không bao giờ thẳng production),
   `verify-backup.sh` (restore + kiểm tra `gon_schema_migrations`/số bảng).
4. **DR runbook** (mục 4 dưới đây) — quy trình + RTO/RPO **mục tiêu**, chưa
   drill.

## 2. Quyết định thiết kế (ghi cho PO review)

| # | Quyết định | Lý do |
|---|---|---|
| D1 | Log = JSON lines qua stdout/stderr; app không tự ship log | Cloud Run/ops log agent là tầng shipping; app giữ sink-agnostic, test được qua `configureObservability` |
| D2 | Whitelist scalar + drop key nhạy cảm + drop nested object (kể cả mảng object) trong `sanitizeLogFields` | Rò rỉ hay đến từ field mới/nested — fail-closed thay vì blacklist |
| D3 | Outbox backlog **không** gate `readyz` (chỉ report `outbox.ok=false` + `errorCode`) | LB readiness flip không giải quyết consumer kẹt; gây instance churn làm backlog tệ hơn. Tín hiệu cho alerting (R1.15/P06 gắn pager) |
| D4 | Migration pending → `not_ready` (fail-closed) | Schema cũ + code mới = lỗi runtime 500 hàng loạt; chặn ở LB là an toàn nhất |
| D5 | `POSTGRES_REQUIRED_TABLES` mở rộng theo schema thật (union mọi `create table` trong migrations) | Kiểm chứng bằng script đối chiếu; readiness trước đây thiếu 14 bảng R1.6–R1.10 |
| D6 | Backup = `pg_dump --format=custom` + sha256 sidecar + `pg_restore --list` verify ngay lúc backup | Custom format cho restore chọn bảng + `--clean`; checksum phát hiện hỏng sớm |
| D7 | Restore **luôn** vào scratch DB trước, `verify-backup.sh` kiểm tra migration ledger + số bảng rồi mới bàn promote | Tránh sự cố restore đè production; backup chưa verify = backup chưa tin được |
| D8 | Access log log `userId` (pseudonymous internal id) nhưng **không** log query string/body | Tương quan audit đủ dùng; query string có thể chứa từ khóa học tập (dữ liệu cá nhân) |

## 4. DR runbook (mục tiêu — CHƯA DRILL)

> Mọi con số dưới đây là **mục tiêu vận hành**, chưa được kiểm chứng bằng
> drill. Sau mỗi drill trên hạ tầng thật, ghi kết quả thực vào mục 6.

**Mục tiêu đề xuất:** RPO ≤ 24 giờ (backup hàng ngày + PITR của managed DB),
RTO ≤ 4 giờ (restore từ backup gần nhất vào instance mới).

### 4.1 Backup định kỳ (cron/Cloud Scheduler — NOT RUN)

1. Hàng ngày: `scripts/backup/backup-postgres.sh` với `DATABASE_URL` của
   production (hoặc dùng automated backup + export của Cloud SQL).
2. Lưu dump + `.sha256` vào bucket versioned; giữ 7 daily + 4 weekly.
3. Sao chép cross-region bản weekly (RPO region-level).

### 4.2 Sự cố mất dữ liệu / hỏng DB (PITR trước, backup sau)

1. Dừng write path (kill switch `feature_flags` nếu cần — xem R1.6).
2. Dùng point-in-time recovery của managed DB nếu thời điểm hỏng nằm trong
   window PITR; nếu không → restore `scripts/backup/restore-postgres.sh` bản
   gần nhất vào **scratch DB**.
3. `scripts/backup/verify-backup.sh` — phải OK (migration ledger + số bảng)
   trước khi promote.
4. Chạy smoke: `/healthz`, `/readyz` (phải `ready` — gồm check migrations),
   login + search + 1 Brew smoke.
5. Mở write path; kiểm tra outbox backlog (`readyz` log/`outbox` check) và
   chạy consumer tới khi backlog = 0.

### 4.3 Mất region / mất hạ tầng

1. Provision lại: Cloud Run service + Cloud SQL (restore như 4.2) + GCS bucket
   (versioned objects còn nguyên nếu bật multi-region).
2. Áp migration: `node scripts/migrate.mjs` (advisory lock chống chạy đôi).
3. Checklist Go-Live P06 dùng lại; checklist đầy đủ nằm trong P06 package.

### 4.4 Sau sự cố

- Ghi timeline, dữ liệu mất (nếu có), thời gian RTO/RPO thực tế vào mục 6.
- Bổ sung bài học vào evidence; cập nhật mục tiêu nếu drill cho thấy lệch.

## 5. NOT RUN — chờ hạ tầng thật (không bịa kết quả)

- **Backup/restore/verify thực thi** với PostgreSQL server thật + pg_dump/
  pg_restore: **NOT RUN** (sandbox không có native PG/`pg_dump`). `bash -n`
  chỉ xác nhận cú pháp.
- **DR drill** (mất DB/mất region, đo RTO/RPO thực tế): **NOT RUN**.
- **`checkPostgresMigrationState`/`checkPostgresOutboxBacklog` trên managed
  PostgreSQL**: PGlite integration không chạy 2 hàm này (dùng `pg.Pool` thật);
  unit-test đã stub semantics. Verify trên staging.
- **Log shipping/alerting thật** (Cloud Logging sinks, pager/chat webhook cho
  `budget_alert`/`readiness_not_ready`): interface + log line sẵn, delivery
  config thuộc P06/ops.
- **Load/soak test** để đặt ngưỡng `GON_OUTBOX_BACKLOG_READY_LIMIT` và ngưỡng
  flood/token bucket theo quan sát thật.
