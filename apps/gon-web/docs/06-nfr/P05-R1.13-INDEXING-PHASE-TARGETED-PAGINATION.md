# P05-R1.13 — Indexing ngoài Unit of Work & targeted pagination

> **Phạm vi:** remediation slice **P05-R1.13** của gate P05 (NOT YET PASS) theo
> lộ trình ủy quyền liên tục 24/10/2026. Bằng chứng trong tài liệu là
> **local/hermetic** (memory adapter + PGlite + fake clock/transport). Đây
> **không** phải bằng chứng trên managed PostgreSQL, Cloudflare, corpus thật
> 20k–100k chunks hay production.

## 1. Yêu cầu của R1.13 (theo kế hoạch R1 và các evidence trước)

Hai tàn dư hiệu năng/kiến trúc đã được các evidence trước đánh dấu:

1. **`indexModuleVersion` chạy trong Unit of Work** — R1.5 §6.6: "cần tách khi
   thay embedding provider thật". Trong UoW, mỗi chunk của ModuleVersion gọi
   `embeddingProvider.embed()` (latency mạng khi chuyển sang Gemini
   embeddings) trong khi transaction đang mở (Postgres giữ transaction +
   identity map trong suốt chuỗi call).
2. **Targeted pagination còn lại** — R1.2 §5.1/R1.6 §5.3: các list endpoint
   người dùng vẫn chạy trong UoW; với `GON_STORE=postgres` điều đó có nghĩa
   `loadRepositories()` load **toàn bộ** bảng (kể cả chunk corpus) vào identity
   map ở đầu transaction chỉ để render một màn hình danh sách 20 dòng.

Kèm theo (housekeeping từ R1.12): `deploy/edge-rate-limit/README.md` liệt kê
`cloudflare-worker.js` nhưng tệp không tồn tại.

## 2. Đã triển khai

### 2.1 Tách indexing ModuleVersion khỏi Unit of Work (Brew pipeline)

Pipeline Brew queued từ R1.5 đã là 3 phase (UoW → AI ngoài transaction → UoW).
R1.13 kéo nguyên tắc đó xuống phần indexing:

- **Phase index-1 (ngoài mọi transaction):** `GonService.prepareModuleVersionChunks(version)`
  — pure data preparation + gọi `embeddingProvider.embed()` từng chunk. Không
  đọc/ghi repository nào.
- **Phase index-2 (một UoW ngắn):** `GonServiceCore.finishBrewIndexing(work, chunks)`
  — ghi chunk rows, hoàn tất `persist_draft` (chỉ khi chưa hoàn tất), build
  candidate set (dedupe theo `sourceModuleVersionId`), `succeedJob`, settle
  cost budget, emit `module.version.created` + `brew.job.succeeded`.
- **Điểm neo (gating) dùng `payload.stepsCompleted`** — không thêm step name
  mới, giữ nguyên enum `currentStep` của P03 (`openapi.json` không đổi).
- **Fail-closed khi embedding lỗi giữa chừng:** `failBrewIndexing` — job chuyển
  `failed_retryable` (`BREW_FAILED`, `currentStep=persist_draft`), checkpoint
  ModuleVersion đã commit ở phase 3 **giữ nguyên**; retry resume từ checkpoint
  (không generate trùng module).
- **Hai đường vào:** (a) fresh — phase 3 commit ModuleVersion rồi trả index
  continuation; (b) resume — phase 1 thấy `resultModuleVersionId` đã có nhưng
  `persist_draft` chưa hoàn tất (crash sau phase 3) → trả index continuation.
- `indexModuleVersion` (method cũ chạy trong UoW) bị **xóa**, thay bằng cặp
  prepare/commit tách bạch.

### 2.2 Targeted pagination cho 4 list endpoint (ngoài UoW)

- **Port mới `TargetedPaginationPort`** (`targeted-queries.ts`):
  `findAccountStatus`, `listJourneySummaries`, `journeyOwnedBy`,
  `listJourneyCommitSummaries`, `listXpLedgerEntries`, `listProofSummaries` —
  trả `{ rows, total }` (total = filtered count để `hasMore`/`nextCursor`
  đúng như path cũ).
- **PostgreSQL binding:** thêm vào `PostgresTargetedQueries` — LIMIT/OFFSET SQL
  trên cột có index (`journeys_owner_status_updated_idx`,
  `xp_ledger_user_history_idx`, `proofs_owner_level_created_idx`,
  `branch_commits_sequence_unique`); row mappers tách thành hàm dùng chung với
  identity-map loader (`mapJourneyRow`/`mapBranchCommitRow`/`mapXpLedgerRow`/
  `mapProofRow`) nên hai đường hydrate giống hệt nhau.
- **Memory binding:** `MemoryTargetedPagination` + `MemoryGonStore.createTargetedPagination()`
  — cùng filter/sort chính xác với core list (đảm bảo bằng test tương đương).
- **Facade `GonService`:** option `targetedPagination` — khi có, 4 endpoint
  `GET /v1/journeys`, `/v1/journeys/{id}/commits`, `/v1/me/xp-ledger`,
  `/v1/proofs` page **không mở Unit of Work nào** (test đếm transaction = 0);
  khi không có, giữ nguyên path trong UoW (fallback). `runtime.ts` wire port
  với **pool-level executor** chỉ khi `GON_STORE=postgres`.
- **Authz không suy yếu:** account gate replicate đúng ladder của
  `requireActiveUser` (missing/deleted → 401; suspended/deletion_pending/
  onboarding → 403 đúng mã + message); commits của journey người khác → 404
  qua `journeyOwnedBy`.
- **Tiebreak deterministic:** sort thêm `id DESC` cho journeys (theo
  `updated_at`) và proofs (theo `created_at`) trên cả ba path (core, memory,
  SQL) — bỏ phụ thuộc insertion-order khi timestamp trùng millisecond.
  Cursor vẫn là offset opaque — format/khế ước P03 không đổi.
- **DTO mappers tách ra module-level** (`journeyDto`, `proofDto`,
  `journeyCommitDto`, `xpLedgerEntryDto`) dùng chung cho core + facade bypass.

### 2.3 Housekeeping: `cloudflare-worker.js`

Tạo `deploy/edge-rate-limit/cloudflare-worker.js` — worker tối giản đúng như
README mô tả: token bucket in-memory per PoP, read/write tách biệt, default
**240 tokens/4 per sec (read)** và **120/2 (write)** khớp origin policy L2,
response 429 `RATE_LIMITED` + `Retry-After` đúng shape P03. Giữ nhãn
**NOT RUN** (chưa deploy Cloudflare thật, chưa load test).

## 4. Còn mở sau R1.13 (không claim đã đóng)

1. **`listProjects` vẫn trong UoW:** `status`/`nextAction` là state suy diễn
   từ artifacts/search/brew/candidates/journeys — đưa filter vào SQL đòi hỏi
   cột status denormalized hoặc read-model riêng (quyết định sản phẩm +
   migration P03 process). Defer sang lát staging (R1.15/P06) kèm evidence
   EXPLAIN trên corpus thật.
2. **Embedding lúc ingest artifact** (`processTextArtifact`, URL metadata)
   vẫn chạy trong UoW của command ingest — same-class problem nhưng thuộc
   flow đồng bộ khác (không có worker pipeline 3-phase sẵn); cần tách khi
   chuyển Gemini embeddings thật.
3. **Identity-map load-all vẫn còn cho mọi endpoint không phải list** —
   targeted pagination chỉ giải phóng 4 đường đọc nóng; thiết kế lazy-load
   repository là thay đổi kiến trúc lớn hơn (blocker staging như cũ).
4. **EXPLAIN/latency trên corpus 20k–100k chunks, Cloudflare deploy thật,
   concurrency thật cho pagination SQL** — NOT RUN (PGlite single-connection,
   không có hạ tầng).
5. CI GitHub Actions cho merge commit R1.12 không spawn run (đã ghi nhận ở
   lượt trước); kỳ vọng CI branch R1.13 chạy đủ job — `build-storybook` vẫn
   FAIL như `D-SB-01` (fix ở R1.14).

## 5. Quyết định (D1–D9)

- **D1:** Brew indexing tách 2 phase (embed ngoài transaction; commit chunk +
  finalize trong UoW ngắn). Gating bằng `stepsCompleted` — không thêm step
  name mới (P03 enum bất biến).
- **D2:** Fresh path trả index continuation từ phase 3 (checkpoint trước
  fallible work); resume path ở phase 1 dùng checkpoint `resultModuleVersionId`.
- **D3:** Lỗi embedding giữa chừng → `failBrewIndexing` fail-closed retryable
  (`BREW_FAILED`, `persist_draft`), giữ checkpoint; retry không duplicate.
- **D4:** `module.version.created`/`brew.job.succeeded` chỉ emit khi hoàn tất
  step trong index-2 → crash + resume không nhân bản events (exactly-once theo
  checkpoint).
- **D5:** `TargetedPaginationPort` (pool-level, read-only, ngoài UoW) cho 4
  list đơn-chủ-sở-hữu; `listProjects` cố tình **không** chuyển (lý do §4.1).
- **D6:** Authz qua port replicate đúng ladder `requireActiveUser` +
  `journeyOwnedBy` 404 — bypass UoW không được phép suy yếu 401/403/404.
- **D7:** Tiebreak `id DESC` cho mọi sort timestamp trên 3 path (core/memory/
  SQL) — deterministic cross-store; cursor offset opaque giữ nguyên (P03).
- **D8:** Row mappers PG tách dùng chung loader + pagination (tránh hydrate
  lệch); memory binding có test tương đương song song hai path trên cùng store.
- **D9:** `cloudflare-worker.js` được **tạo** (không cắt README) vì module
  README đã mô tả đúng vai trò optional của nó; nhãn NOT RUN giữ nguyên.
