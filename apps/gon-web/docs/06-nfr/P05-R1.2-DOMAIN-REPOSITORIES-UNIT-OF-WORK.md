## 1. Kiến trúc đã triển khai

```text
HTTP routes / Auth callbacks / actor resolution
        │
        ▼
GonService (async application facade)
        │  một use case = một Unit of Work
        ▼
GonStore.runInTransaction(repositories)
        ├─ MemoryGonStore: clone identity map → chạy → swap khi thành công
        └─ PostgresGonStore:
             BEGIN SERIALIZABLE
             → load normalized aggregates vào identity map
             → domain core + SQL hybrid Search (savepoint)
             → diff/flush changed aggregates
             → COMMIT / ROLLBACK
        │
        ▼
GonServiceCore chỉ phụ thuộc GonRepositories
```

Các file boundary chính:

- `src/server/repositories.ts` — `GonRepositories`, `GonStore`, repository collections theo aggregate và identity-map dùng chung;
- `src/server/memory-store.ts` — local/test Unit-of-Work adapter có clone/rollback và serialize transaction trong một process;
- `src/server/postgres-store.ts` — PostgreSQL loader/flusher cho normalized schema, transaction runner và retry serialization;
- `src/server/postgres-search.ts` — SQL hybrid Search, nay được gắn vào Unit of Work qua `repositories.hybridSearch`;
- `src/server/service.ts` — domain core giữ logic VS1 nhưng không còn truy cập Map/concrete store; facade async mở transaction cho từng public use case;
- `src/server/runtime.ts` — chọn tường minh `memory` hoặc `postgres`, không fallback âm thầm.

Nested facade calls trong một operation hợp lệ (ví dụ tạo dev user + dev session) join cùng Unit of Work bằng `AsyncLocalStorage`, thay vì mở transaction lồng nhau.

## 2. Aggregate mapping sang PostgreSQL

| Nhóm aggregate | Bảng normalized chính | Ghi chú mapping |
|---|---|---|
| Identity/onboarding | `gon_users`, `role_grants`, `identity_links`, `user_profiles`, `invites`, `age_attestations`, `consents` | Roles được sync qua active grants; attestation chỉ insert |
| Project/artifact | `learning_projects`, `source_artifacts`, `artifact_upload_sessions`, `content_chunks`, `chunk_embeddings` | Raw prompt FK deferred; chunk bị loại bỏ được tombstone bằng `deleted_at`; vector giữ profile 768D |
| Job/module | `async_jobs`, `modules`, `module_versions`, `concepts`, `module_concepts`, `citation_references` | Graph là canonical JSONB; concepts/citations được project ra bảng quan hệ khi insert |
| Search/Brew/output | `search_attempts`, `search_attempt_artifacts`, `search_results`, `brew_jobs`, `candidate_sets`, `output_candidates`, `ranking_snapshots`, `ranking_snapshot_items` | Link/results/items được replace trong cùng transaction của aggregate cha |
| Learning | `journeys`, `branch_commits`, `learning_attempts`, `learning_attempt_artifacts`, `assessment_results`, `mastery_states` | `rubric_snapshot` được lấy từ graph của đúng module version/rubric version khi assessment được append |
| XP/proof/moderation | `xp_ledger_entries`, `xp_projections`, `proofs`, `proof_artifacts`, `proof_verification_events`, `reports`, `moderation_cases` | Projection được refresh từ ledger; proof insert/đổi level tạo verification event |
| Operations | `outbox_events`, `audit_logs`, `idempotency_records` | Idempotency lưu actor/operation/key riêng; Audit chỉ insert |

### Bất biến được adapter tôn trọng

- `age_attestations`, `branch_commits`, `xp_ledger_entries` và `audit_logs`: adapter chỉ insert; diff update/delete sẽ bị từ chối trước khi chạm trigger append-only.
- `assessment_results`: chỉ append khi assessment mới/thay đổi; attempt load lại dùng assessment mới nhất.
- `module_versions`: update chỉ ghi `visibility`, `publication_status`, `grounding_status`; adapter tự kiểm tra các field content/identity bất biến và từ chối nếu domain cố sửa graph đã persist.
- Flush đi theo FK dependency order. Project hiện tại (`current_search_attempt_id`, `current_brew_job_id`, `current_candidate_set_id`) và journey `head_commit_id` được ghi ở vòng pointer cuối sau khi row đích tồn tại.
- Attempt update rời trạng thái `draft` được flush trước attempt draft thay thế để tôn trọng partial unique index “một draft cho mỗi journey/node”.
- XP sequence được khôi phục từ ledger đã load; `xp_projections` phản ánh entry sequence cao nhất sau mỗi transaction có XP mới.

## 3. Transaction và concurrency semantics

### Memory adapter

- Chỉ dùng cho local/test.
- Mỗi transaction chạy trên identity map đã clone; thành công mới swap vào store chính, thất bại không leak mutation.
- Transaction được serialize trong process để hai clone không ghi đè nhau. Đây không phải cơ chế scale ngang.

### PostgreSQL adapter

- Production runner dùng một `pg` client riêng cho transaction: `BEGIN ISOLATION LEVEL SERIALIZABLE`, commit/rollback tường minh và luôn release client.
- Store retry tối đa ba lần cho SQLSTATE `40001` (serialization failure) và `40P01` (deadlock); lỗi khác không retry.
- Hybrid Search chạy trên cùng transaction nhưng sau một savepoint. Nếu SQL Search lỗi, domain có thể ghi trạng thái `failed_retryable` rồi commit thay vì để toàn transaction ở trạng thái aborted.
- Snapshot/diff chỉ flush aggregate đã thay đổi; record không đổi không bị update lại.

## 4. Runtime và readiness

`GON_STORE=postgres` hiện được wired thật với điều kiện:

1. `DATABASE_URL` hợp lệ được cấu hình;
2. sáu migrations đã được áp dụng bằng `npm run db:migrate` trong bước vận hành riêng — web runtime không tự chạy migration;
3. pool/TLS cấu hình qua các bound sẵn có tại `src/server/db.ts`.

Nếu thiếu `DATABASE_URL`, runtime fail-fast. Nếu chọn store không hỗ trợ, runtime cũng fail-fast thay vì fallback memory.

Readiness nay yêu cầu cả ba điều kiện:

- runtime store khởi tạo được;
- PostgreSQL ping thành công trong timeout;
- toàn bộ Auth/domain tables bắt buộc tồn tại. Một database rỗng trả `DATABASE_SCHEMA_NOT_READY`, không được coi là ready chỉ vì `select 1` thành công.

## 6. Ranh giới còn mở — không được diễn giải quá mức

1. **Identity-map load:** PostgreSQL Unit of Work hiện load các aggregate vào identity map ở đầu transaction và flush diff. Đây là lựa chọn correctness-first cho R1.2, chưa phải targeted-query/pagination design cho corpus lớn. Performance trên 20k–100k chunks vẫn thuộc blocker staging.
2. **External calls trong use-case transaction:** embedding/Brew đồng bộ hiện vẫn nằm trong transaction của use case. Durable worker/queue ở lát cắt sau phải rút ngắn transaction và thêm lease/retry/reconciler.
3. **Object bytes:** metadata của artifact/upload session đã durable, nhưng bytes của `/api/local-uploads` vẫn ở process-local simulator. PostgreSQL không lưu raw binary; signed private object storage vẫn chưa wired.
4. **Dev sessions:** chỉ là boundary non-production và process-local. Auth.js database sessions là đường production; Google E2E/revoke trên staging vẫn chưa chạy.
5. **Jobs/outbox:** rows đã persist transactionally, nhưng chưa có queue worker, lease/heartbeat, publisher, retry/backoff hay reconciler.
6. **Authorization tầng DB:** owner checks vẫn ở application/SQL Search; database roles/RLS chưa được chốt hoặc kiểm chứng.
7. **Quotas/cost:** quota hiện được tính từ aggregate đã load trong transaction; quota reservations, edge/distributed limits và provider budget/circuit breaker vẫn mở.
8. **AI/Search quality:** local deterministic embedding/Brew/assessment vẫn là adapter kiểm thử. Gemini/ADK thật, representative corpus và golden evaluation vẫn **NOT RUN**.
9. **Ops/DR:** chưa có managed PostgreSQL staging, metrics/traces/alerts, backup/PITR/restore drill, DAST/load/accessibility browser evidence.
