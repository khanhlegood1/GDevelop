## 1. Phạm vi lát cắt

Bổ sung lớp L1–L3 cho `B-P05-06` bên cạnh persistent quotas/kill switches/
circuit breaker đã có từ R1.6:

1. **Token bucket per-IP / per-user** (read/write classes) — giới hạn tốc độ
   request, state **chia sẻ giữa các app instance** qua PostgreSQL.
2. **Flood guard idempotent** — strike window ngắn + penalty box nhân đôi theo
   lần tái phạm; request **replay cùng `Idempotency-Key` được miễn trừ**
   (không tốn token, không tăng strike) nên client retry storm không tự khóa
   chính mình, trong khi flood distinct request vẫn bị chặn.
3. **Budget alert hooks** — khi usage ngân sách AI (`brew_cost_units_per_day`)
   vượt ngưỡng 50/80/100%, mỗi (user, quota window, threshold) được claim
   **đúng một lần** trong state phân tán → emit outbox `guardrail.budget_alert`
   + optional `BudgetAlertSink` (ops hook). Hooks là tín hiệu quan sát, không
   thay enforcement — enforcement vẫn là budget reservation R1.6.
4. **Per-IP/edge module đóng gói** cho hạ tầng thật
   (`deploy/edge-rate-limit/`) — Cloud Armor policy, nginx snippet, checklist.

## 2. Kiến trúc & quyết định thiết kế (ghi cho PO review)

| # | Quyết định | Lý do |
|---|---|---|
| D1 | Thuật toán token bucket + flood strike là **thuần hàm** (`consumeBucketInMemory`, `applyFloodStrike`) — memory store, PostgreSQL store và edge runtime dùng chung một implementation | Tránh lệch hành vi giữa các binding; test được không cần DB |
| D2 | PostgreSQL binding dùng **optimistic CAS trên cột `version`** (read → compute → `update ... where version = seen`), thua CAS thì tính lại (bounded retry) | Nhiều instance cùng enforce chính xác; tránh race timestamp-precision (timestamptz round-trip mất microsecond) |
| D3 | State ghi **ngoài identity-map UoW** (targeted SQL qua `SqlExecutor`) | Rate-limit state là hạ tầng cross-request, phải sống sót khi request rollback; không phải domain state |
| D4 | Khi mở penalty box: **reset strikes + window**, giữ `offenseCount` để nhân đôi block tiếp theo (cap `blockMaxMs`) | Box là hình phạt; giữ strikes cũ sẽ khóa vĩnh viễn subject dùng chung (NAT/`unverified`) |
| D5 | Mọi subject (IP/user) **hash sha256 + salt** (`GON_ABUSE_HASH_SALT`) trước khi lưu; không bao giờ lưu IP thô | IP là dữ liệu cá nhân — align với posture privacy R1.7 |
| D6 | `trustProxyHeaders=false` (mặc định) → IP scope suy biến về subject `"unverified"` dùng chung | Header `X-Forwarded-For` không qua edge tin cậy là attacker-controlled; per-IP thật thuộc về L1 edge (đóng gói, NOT RUN). Nguyên tắc này trùng triết lý `trustProxyHeaders` sẵn có |
| D7 | Idempotent replay exemption dựa trên marker TTL 15 phút (`abuse_idempotency_markers`) | Tách bạch với `idempotency_records` (replay business result) — mục đích ở đây là flood accounting |
| D8 | Từ khóa lỗi dùng **`RATE_LIMITED`** (429) — đã liệt kê sẵn trong P03 `API-CONTRACT.md` §errors; thêm header `Retry-After` qua `retryAfterSeconds` của `ApiError` | Không mở rộng P03 contract (contract bị khóa); chỉ dùng code đã được chuẩn |
| D9 | Enforcement 2 tầng: HTTP `handleV1` (per-IP + per-user, mọi request) + service `enforceUserRateLimit` (8 luồng tốn kém: project/artifact/upload/search/brew/submit) | Chặn được cả caller không qua HTTP; `GonService` facade giữ **một** controller chia sẻ xuyên suốt các UoW core (token state không reset theo transaction) |
| D10 | `GonService` mặc định tự tạo controller memory + policy hào phóng (vd `userWrite` 600 burst / 10 token/s) | Test/production cũ không bị break; production composition (`runtime.ts`) luôn bật với store PostgreSQL + policy từ `GON_ABUSE_*` |
| D11 | Budget alert claim dedupe qua unique `(user_id, quota_key, window_start, threshold_pct)` + `insert ... on conflict do nothing` | Exactly-once across instances mà không cần coordinator |
| D12 | Migration `0010`: RLS ENABLE-not-FORCE; 3 bảng hash-keyed **deny-by-default (không user policy)**; `budget_alert_claims` user-scoped theo mẫu 0008; role setup vẫn deploy-time | Nhất quán mô hình RLS R1.6 |

  snippet / Cloudflare worker — **NOT RUN** (không có LB/nginx thật trong
  sandbox). Kèm checklist load-test k6/vegeta cho staging.

  + log structured; deliver tới webhook/chat/pager thuộc R1.11 observability.

  ngoài phạm vi sandbox.
